# Agent Evaluation Lab v0.7.0

This release focuses on making Agent Evaluation Lab easier to demonstrate, package, and publish reproducibly.

## Highlights

- **End-to-end agent demo:** includes a credential-free prompt-agent benchmark with deterministic reference and intentionally partial fixture adapters.
- **Verified comparison pipeline:** demo CI runs both adapters against the same fingerprinted benchmark and generates JSON, HTML, and JUnit outputs.
- **Distribution validation:** builds wheel and source distributions, validates them with Twine, installs the wheel in a clean virtual environment, and smoke-tests all CLI entry points.
- **PyPI package metadata:** adds project URLs, keywords, and classifiers for package distribution.
- **Trusted Publishing:** adds a GitHub OIDC workflow for PyPI publishing without long-lived API tokens.
- **Release safety:** the publish workflow verifies that the GitHub release tag exactly matches the package version before uploading.

## Install from source

```bash
git clone https://github.com/adityasupag1/agent-evaluation-lab.git
cd agent-evaluation-lab
python -m pip install -e ".[dev]"
```

After the first successful Trusted Publishing run, the package is intended to support:

```bash
pip install agent-evaluation-lab
```

## Demo

```bash
agent-eval-validate examples/agent-demo-benchmark.json

agent-eval examples/agent-demo-benchmark.json \
  --agent-config examples/agents/demo-reference.json \
  --label demo-reference \
  --output demo-results/reference.json

agent-eval examples/agent-demo-benchmark.json \
  --agent-config examples/agents/demo-partial.json \
  --label demo-partial \
  --output demo-results/partial.json

agent-eval-compare \
  demo-results/reference.json \
  demo-results/partial.json \
  --html-output demo-results/comparison.html
```

Expected deterministic fixture results:

| Adapter | Result |
| --- | ---: |
| demo-reference | 5/5 (100%) |
| demo-partial | 3/5 (60%) |

These are fixture-agent results used to demonstrate the evaluation plumbing; they are not benchmark scores for real LLM products.

## Publishing

The release workflow uses PyPI Trusted Publishing via GitHub OIDC. It does not require a stored `PYPI_TOKEN`.

For the first publish, the PyPI pending publisher and GitHub `pypi` environment must already be configured. See [docs/pypi-publishing.md](../pypi-publishing.md).
